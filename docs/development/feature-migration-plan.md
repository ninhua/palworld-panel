# PalPanel 功能移植计划

基线：`ninhua/palworld-panel` 的 `custom-stable` 分支。

| 顺序 | 功能 | 状态 |
|---|---|---|
| 1 | 双模式面板更新与健康回滚 | 已完成 |
| 2 | 配置版本库 | 已完成 |
| 3 | 存档差异 | 已完成 |
| 4 | 崩溃守卫 | 代码完成，等待 GitHub CI 和实机验证 |
| 5 | 通知与事件中心 | 代码完成，等待 GitHub CI 和 Webhook 实机验证 |
| 6 | 诊断与支持包 | 未开始 |
| 7 | 多用户角色与高风险二次验证 | 未开始 |
| 8 | 统计、RCON 控制台和灾备 | 未开始 |
| 9 | 地图、运维剧本和玩家治理 | 未开始 |
| 10 | 房主模式、生产订单和据点改名 | 未开始 |

第 1 项包含：

- systemd 环境：外部 root 更新器切换完整 Release。
- 启动脚本环境：沿用原补丁的 `syscall.Exec` 原地热更新。
- 两种模式均校验官方 SHA-256、候选版本和启动健康状态。
- exec 模式只允许更新清单明确声明的“仅主程序”Release。

第 2 项包含：

- 每次成功应用配置时记录私密快照、父版本和修改字段。
- 历史差异对普通字段显示前后值，对密码字段仅显示配置状态。
- 恢复历史版本先生成草稿，再复用现有停服、启动、健康检查与失败恢复事务。
- 默认保留最近 50 个修订，过期私密文件进入可重试清理队列。

第 3 项包含：

- 每次成功索引记录脱敏压缩快照，相同指纹不重复。
- 快照按世界目录哈希隔离，切换存档源不会混合历史。
- 支持玩家、公会、基地、帕鲁、容器和全局物品数量变化。
- 每个世界默认保留 24 份、总体积限制 512 MiB，并校验快照 SHA-256。

第 4 项包含：

- 5 秒轮询运行状态，10 分钟内累计 3 次异常退出、OOM 或容器重启时熔断。
- Docker 模式先将 restart policy 改为 `no`，再停止崩溃循环容器。
- Windows 模式识别非 PalPanel 生命周期操作导致的进程退出。
- 熔断状态和最近 50 条事件持久化，PalPanel 重启后继续阻止启动。
- 管理员可在监控页打开诊断控制台，确认后仅解除熔断，或解除并启动服务器。

第 5 项包含：

- 监控告警、崩溃守卫和失败后台任务统一形成持久事件。
- 相同根因按稳定去重键累计次数，已解决事件再次发生时自动重新打开。
- 管理员可确认、解决或重新打开事件，全部状态变化写入时间线和审计。
- 可选 HTTPS/回环 Webhook 使用 HMAC-SHA256 签名和固定 Delivery ID，最多重试 6 次。
- Webhook 载荷不包含日志正文、文件路径、任务原始错误或签名密钥。

每项功能单独制作源码增量包。开始下一项前先同步最新 `custom-stable`。
