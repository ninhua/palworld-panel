# 功能移植已知问题

## 房主存档 UID 重映射

- `ItemContainerSaveData[n].Value.CustomVersionData` 是原样保留的版本元数据。合作房主固定源 UID 的 16 字节序列可能在该字段中作为哨兵模式出现，不代表玩家引用。
- 只有 `Level.sav`、精确 `ItemContainerSaveData` 路径、source candidate 和固定房主 UID 的组合会降级为警告；任意其他 opaque candidate 仍中止迁移。
- 该修复不重写未知字节，也不放宽 typed UID 转移数量、玩家文件名、输入清单、语义指纹或 round-trip 验证。
- exec 热更新后 helper 会在首次房主迁移时按嵌入 SHA-256 自动引导更新；只读安装目录或无法访问对应 GitHub Release 时需使用完整包更新。

## 通知与事件中心

- Webhook 默认关闭，只能通过环境变量启用；修改 URL、密钥或超时后必须重启 PalPanel。
- 远程 Webhook 只允许 HTTPS；HTTP 仅允许回环目标。URL 不允许凭据、查询参数或片段。
- 投递是至少一次语义。网络超时后接收方可能已经处理请求，因此接收方必须按 `X-PalPanel-Delivery` 去重。
- 最多重试 6 次，最终失败只保留脱敏投递状态，不会继续无限重试，也不会反向创建新事件。
- 失败任务事件按任务类型和稳定错误码归并；缺少精细错误码的旧任务可能被归并到通用 `failed` 根因。
- 事件中心不是日志系统，不保存原始错误正文、路径或日志片段；排障仍需进入任务详情、日志或诊断控制台。

## 崩溃守卫

- 默认阈值固定为 10 分钟内 3 次异常；当前版本尚未提供页面自定义阈值。
- Docker 模式依赖完整的 `docker inspect` 生命周期字段；运行时无法提供 OOM、退出码或 restart count 时只能识别状态转换。
- Windows 上由 PalPanel 之外的工具正常关闭 PalServer 也会被视为意外退出，因为面板无法证明该操作是预期生命周期。
- 熔断不会自动恢复。管理员应先检查监控、日志和诊断控制台；配置应用前需选择“仅解除熔断”。服务端更新可在熔断状态执行，但更新后保持停服。
- 解除熔断后，旧事件仍可查看，但统计窗口从恢复时间重新开始；启动失败会立即恢复为熔断状态，避免形成新的无限重启循环。

## 存档差异

- 只有成功生成的结构化索引会进入历史；索引器关闭、解析失败或尚未形成第二份快照时不能比较。
- 快照不是原始存档备份，不能用于恢复世界，只用于只读变化分析。
- 自动索引可能在频繁自动保存期间形成多份快照；每个世界默认最多保留 24 份且总压缩体积不超过 512 MiB。
- 容器明细为避免超大响应只显示摘要；全局物品类别会返回精确总量变化。
- 玩家匹配优先使用标准化 PlayerUID，其次 SteamID，最后昵称；缺少稳定标识且发生改名时可能表现为“移除 + 新增”。

## 配置修订历史

- 修订快照包含 Palworld 管理密码和服务器加入密码，只能存放在面板私有数据目录；API 和日志不得输出原文或快照路径。
- 历史版本使用当前配置 schema 重新校验。当前 schema 收紧已知字段约束后，不兼容修订会拒绝生成回滚草稿；未知原始字段仍按现有配置编辑器规则保留。
- 回滚不是直接覆盖：先生成草稿，再执行正常配置应用，因此运行中的 PalServer 可能按既有安全流程短暂停止并重新启动。已有配置应用事务进行中时会拒绝生成新的回滚草稿。
- 默认保留最近 50 个修订；超出数量的私密文件由可重试清理队列异步删除。

## 双模式面板更新

- `0.8.30` 本身没有 exec 通道；无 systemd 环境首次升级到 `0.8.31` 需要由外层启动脚本安装完整 Release。运行 `0.8.31` 后，后续兼容版本才可从面板内使用 exec 热更新。
- exec 模式只能安全更新主程序。Release 的 `panel-update.json` 声明需要同步更新侧车、控制脚本或安装结构时，面板会拒绝 exec 更新。
- exec 更新会让面板 HTTP 连接短暂断开，但 PID 保持不变，PalServer 与侧车不停止。
- 进程被 `SIGKILL` 或宿主机在健康验证期间断电时，事务会在下次启动继续检查并按标记回滚；外层平台不再重新启动面板时需要人工重启容器。
- 运行目录必须允许当前面板用户写入 `bin/palpanel` 和同目录备份文件。只读目录只能使用 external 模式。
- 从 `0.8.28` 或更早版本首次使用 external 模式时，仍需运行新版安装脚本或 `palpanelctl install` 安装 root 更新器和 systemd 路径单元。
- external 模式目前只用于 Linux amd64 systemd 正式安装；Windows 继续使用 Windows 升级程序。

## 诊断控制台

- 主机终端执行默认关闭，设置 `PALPANEL_DIAGNOSTIC_SHELL_ENABLED=true` 并重启 PalPanel 后才会开放。
- 诊断接口只接受管理员浏览器会话；API Key 和关闭登录验证的部署不能调用。
- 命令以 PalPanel 服务账号权限执行，不提供容器或文件系统沙箱；调试结束后必须重新关闭。

## 验证环境

- 本地执行环境只有 Go `1.23.2`，仓库要求 Go `1.25.12`，因此完整 Go 测试由 GitHub Actions 验证。
