# PalPanel 自定义版 0.8.25

本版本修复 Linux 正式安装环境中面板热更新无法写入并替换自身程序的问题。

## 修复

- 正式安装器将当前版本的 `bin` 目录设置为 `root:palpanel`、权限 `775`。
- systemd 沙箱继续使用 `ProtectSystem=strict`，仅额外允许面板写入 `/opt/palpanel/current/bin`。
- 面板的配置、后端资源、systemd 文件和其他版本目录仍由 root 权限保护。
- 保留原有更新安全流程：下载完整 Release、校验 `SHA256SUMS`、探测候选版本、备份旧二进制、同目录原子替换，并用 `exec` 保持进程 PID。
- 恢复旧补丁热更新在 `exec` 前主动清理下载暂存目录的行为，避免成功更新后遗留完整安装包。

## 原因

旧补丁热更新依赖面板进程能够在当前二进制目录创建暂存文件、备份和重启标记。切换到完整源码 Release 后，正式安装器将版本目录设为 root 所有，同时 systemd 的 `ProtectSystem=strict` 只放行 `/var/lib/palpanel`，导致更新任务在创建暂存目录时被拒绝。

## 首次修复安装

现有安装中的旧服务权限无法通过已经失效的面板热更新自行修复。请先手动下载并安装本版本一次：

```bash
sudo ./palpanelctl install --docker --listen 0.0.0.0:63101
```

安装 `0.8.25` 后，后续版本可继续从面板内执行热更新。

## 验证

- 云端安装测试检查当前版本 `bin` 目录的权限和所属组。
- 云端安装测试检查生成的 systemd 单元仅放行数据目录与当前版本 `bin` 目录。
