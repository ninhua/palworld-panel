# 0.8.81-raid-base1

## 袭击与 Boss 领域拆分

现有多波次活动被重新定义为“袭击”。袭击不再以任意坐标作为配置入口，而是绑定服务器存档中的据点。固定坐标 PalTemplate 召唤将由后续独立 Boss 模块负责。

## 据点绑定

袭击模板在元数据中保存 `raid_base_id`。执行器在每一波开始前从当前存档索引解析据点位置。以下情况会阻止执行：

- 存档索引不可用；
- 据点已被删除或 ID 不存在；
- 据点坐标无效。

模板中原有的 `location` 字段仅作为旧数据库结构的快照，不作为袭击执行回退值。

## 混合波次

波次元数据新增 `spawn_groups`：

```json
{
  "raid_base_id": "BASE_ID",
  "spawn_groups": [
    {
      "name": "主力",
      "pal_template_file": "raid_boss.json",
      "pal_id": "Anubis",
      "level": 55,
      "count": 1,
      "spawn_radius": 250,
      "capturable": false
    },
    {
      "name": "护卫",
      "pal_template_file": "raid_guard.json",
      "pal_id": "ChickenPal",
      "level": 35,
      "count": 8,
      "spawn_radius": 500,
      "capturable": true
    }
  ]
}
```

每个生成组通过现有 PalDefender `/summon` 执行器依次生成。前序组已成功而后续组失败时，执行结果标记为 `uncertain`，防止自动重试造成重复生成。

## 前端

新增袭击设计器：

- 据点搜索和选择；
- 多波次编辑；
- 每波多模板生成组；
- 新玩家礼包同款 PalTemplate 组合筛选；
- 自动执行队列启动；
- 当前运行记录及手动执行下一波。

旧 Boss 管理页面保留为袭击高级管理页，用于奖励、定时计划和历史审计。
