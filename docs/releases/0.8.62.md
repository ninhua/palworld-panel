# PalPanel patch 0.8.62

## PalDefender 商城自动交付

本版在 `0.8.61` 积分商城基础上接入 PalDefender 自动发放，并保留人工交付回退路径。

### 自动交付类型

- `paldefender_items`：按商品 Payload 发放物品。
- `paldefender_pal_templates`：按商品 Payload 发放帕鲁模板。
- 订单数量会乘算物品数量或重复帕鲁模板列表。
- 创建自动商品时校验 Payload、条目数量、标识符和最终发放上限。

### 订单安全状态机

- 创建订单后先完成积分预留和库存占用，再调用 PalDefender。
- PalDefender 成功后记录本地交付凭据，再提交积分预留。
- 如果积分结算失败，订单保留 `succeeded`，后续重试只结算积分，不会再次发放。
- 明确失败进入 `failed`，允许安全重试或取消退款。
- 超时、连接中断、无效响应和 PalDefender 5xx 进入 `processing`，禁止重试和退款，要求管理员人工核对。
- 管理员可在确认已发放后人工完成订单，或在确认未发放后重置交付状态。

### 数据库迁移

- 自动迁移 `0.8.61` 的仅人工交付 CHECK 约束。
- 新增交付状态、尝试次数、最近尝试时间和交付凭据字段。
- 旧商品和旧订单原样保留，不会自动触发 PalDefender。

### 面板页面

积分商城页面新增：

- 人工、PalDefender 物品和帕鲁模板三种交付方式。
- 自动生成 Payload 示例。
- 交付状态、尝试次数、失败原因和最近尝试时间。
- 自动交付、失败重试、人工确认和状态重置操作。
- 异常交付汇总。

### API

新增：

```text
POST /api/shop/orders/{id}/deliver
POST /api/shop/orders/{id}/delivery/reset
```

OpenAPI 当前共包含 307 个操作，新增路由已同步到正式契约。

### 版本锁步

以下版本均同步更新为 `0.8.62`：

- 后端运行时 `patchVersion`
- OpenAPI `PatchInfo.patch.version`
- 自动生成的 TypeScript API 合约
