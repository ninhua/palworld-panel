# PalPanel 自定义版 0.8.45

发布日期：2026-07-30

本版本修复专用地图资源仓库已经成功鉴权和下载，但因目录及 POI 文件名不符合面板预设结构而导致 Linux、Windows 发布打包失败的问题。

## 地图资源布局自动发现

- 保留标准 `map/palops/data/default-pois.<locale>.json` 布局的直接支持。
- 资源仓库使用自己的目录结构时，递归发现文件名或目录名包含 `poi`、`marker`、`location` 的 JSON 数据。
- 支持 JSON/GeoJSON 顶层数组、FeatureCollection，以及 `pois`、`items`、`markers`、`locations`、`data`、`features`、`points`、`records` 包装字段。
- 支持按地图或类别分组的嵌套对象，并合并同一语言的多个 POI 文件。
- 支持 POI 名称使用字符串或 `zh-CN`、`en-US`、`ja-JP` 多语言对象。
- 支持常见的 `poiId`、`mapId`、`position.x/y`、`coordinates` 和 GeoJSON `properties`/`geometry.coordinates` 字段。
- 单份 POI 数据会生成三种语言运行时文件；三语言源文件存在时仍分别使用并执行 ID、地图、类别和坐标一致性校验。

## 瓦片目录归一化

- 自动发现路径末尾符合 `<z>/<x>/<y>.webp` 的 XYZ 瓦片组。
- 根据目录中的 `palpagos`、`palworld`、`mainmap`、`worldtree` 等标识识别两张地图。
- 将资源仓库原生目录统一转换为 `/map/palops/tiles/palpagos` 与 `/map/palops/tiles/world-tree`。
- 继续严格要求两张地图各包含完整 0–4 级金字塔，并检查 WebP 文件头、文件大小和 Git LFS 指针。
- 无法识别时，错误信息会列出发现的 JSON 文件或 XYZ 瓦片组，便于直接定位资源仓库结构。

## 版本同步

- 后端补丁版本由 `0.8.44` 更新为 `0.8.45`。
- OpenAPI `PatchInfo.patch.version` 常量及前端生成契约同步为 `0.8.45`。
- 新增 `palops-resource-layout-discovery` 功能标识。

## 升级注意事项

- `PALPANEL_MAP_ASSETS_TOKEN` 配置保持不变。
- 不需要调整 `palpanel-assets` 仓库现有目录；重新运行发布工作流即可由同步器完成归一化。
- 已发布的 `v1.3.0-custom.0.8.44` 不应覆盖，新发布标签为 `v1.3.0-custom.0.8.45`。
