# PalPanel 自定义版 0.8.31

发布日期：2026-07-29

## 新功能

- 面板更新新增 `auto`、`external` 和 `exec` 三种选择。
- 无 systemd 的启动脚本或便携环境可沿用原补丁机制，通过 `syscall.Exec` 原地热更新主程序，PID 保持不变。
- systemd 正式安装继续使用独立 root 更新器切换完整 Release。
- 更新状态接口返回实际选择的模式和说明。

## 安全与回滚

- exec 热更新校验官方 `SHA256SUMS`、包内 `checksums.txt` 和候选程序版本。
- Release 新增 `panel-update.json`，明确是否允许只替换 `bin/palpanel`；需要侧车或安装结构变更时会拒绝 exec 更新。
- 新进程必须连续三次通过 `/api/ready` 和 `/api/patch/info` 目标版本验证。
- 启动错误、监听失败、验证超时或版本不匹配时恢复旧主程序，并再次通过 `syscall.Exec` 启动旧版本。
- 成功后保留最近四份主程序备份。

## 升级说明

- 启动脚本环境不需要增加 systemd，也不需要改造为监督器。
- 无 systemd 的 `0.8.30` 首次升级到本版本仍由外层 `start.sh` 安装完整 Release；本版本运行后，后续兼容版本可直接从面板内热更新。
- 默认 `PALPANEL_UPDATE_MODE=auto`；无 systemd 时会自动使用 exec。
- 强制指定可使用 `PALPANEL_UPDATE_MODE=external` 或 `PALPANEL_UPDATE_MODE=exec`。
- PalServer、`sav-cli` 和 `palcalc-bridge` 不会因 exec 热更新停止。

## 已知限制

- exec 模式只更新主程序。`panel-update.json` 声明需要其他文件的 Release 必须通过 external 模式或部署脚本升级。
- Windows 不使用该 exec 通道。

## 验证重点

- GitHub Actions 的 Go 包覆盖率最低门槛统一调整为 50%。
- 修正 exec 热更新版本不匹配测试使用了相同目标版本、导致 Linux CI 失败的问题。
- 在无 systemd 的启动脚本环境点击更新，外层脚本等待的 PalPanel PID 应保持不变。
- 更新后 `/api/ready` 返回 ready，`/api/patch/info` 的 `build.version` 为目标版本。
- 模拟目标版本错误或就绪失败时，应自动恢复旧二进制并重新启动。
- systemd 安装仍应选择 external，并通过完整包健康回滚测试。
