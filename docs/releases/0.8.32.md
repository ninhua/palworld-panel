# PalPanel 自定义版 0.8.32

发布日期：2026-07-29

## 新增

- 设置页新增“配置修订历史”，自动记录 `PalWorldSettings.ini` 的活动基线和每次成功应用后的版本。
- 支持将任意历史修订与当前配置进行字段级比较。
- 支持从历史修订生成回滚草稿，并通过现有配置应用事务执行恢复。
- 每条修订记录包含 SHA-256、父版本、来源、修改字段和创建时间。

## 安全

- 配置快照保存在面板私有数据目录，目录权限为 `0700`，文件权限为 `0600`。
- API 不返回快照文件路径。
- `AdminPassword` 和 `ServerPassword` 不返回历史值或当前值，只显示是否已经配置。
- 历史版本必须通过当前 schema 校验，不兼容版本不会生成回滚草稿。
- 配置应用事务进行中拒绝创建新的回滚草稿，尚未通过健康检查的临时配置不会进入正式修订历史。
- 修订快照读取和清理只接受固定私密目录及与修订 ID 对应的文件名，拒绝路径重定向。

## 回滚行为

- 点击恢复只生成草稿，不会立即修改活动配置。
- 应用回滚草稿时复用现有安全停服、原子写入、重新启动和连续健康检查。
- 新配置启动或验证失败时，自动恢复应用回滚草稿之前的配置。
- 默认保留最近 50 个修订，超出部分通过可重试私密文件清理队列删除。

## 接口

- `GET /api/config/palworld/revisions`
- `GET /api/config/palworld/revisions/{id}/diff`
- `POST /api/config/palworld/revisions/{id}/restore`

## 验证重点

- 修正配置修订历史组件传入中文 fallback 提示时与通用错误解析函数签名不一致、导致前端 TypeScript 构建失败的问题。
- 修订列表和差异响应不得包含密码原文或私密快照路径，密码字段匹配不区分大小写。
- 生成回滚草稿后，活动 `PalWorldSettings.ini` 必须保持不变。
- 应用成功后应新增修订；健康检查失败时活动配置和运行状态应恢复。
- 数据库只保留最近 50 条修订，并可靠清理对应私密文件。
- GitHub Actions 执行 Go、前端、OpenAPI、Linux/Windows 打包和安全检查。

完整比较：`v1.3.0-custom.0.8.31...v1.3.0-custom.0.8.32`
