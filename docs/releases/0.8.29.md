# PalPanel 自定义版 0.8.29

## 新功能

- 新玩家礼包新增“初始科技”配置，可选择不处理、解锁全部科技或发放科技点。
- “解锁全部科技”通过 PalDefender `learntech <UserId> all` 对应的 REST 接口执行；后端会将 `all` 标准化为 PalDefender 接受的 `All`。
- 科技点可分别配置普通科技点和古代科技点；选择发放科技点时，两项至少一项大于 `0`。
- 科技计划会在礼包任务创建时冻结，后续修改全局配置不会改变已经排队或重试中的任务。
- 发放进度和事件日志新增科技阶段，失败后可沿用现有“补发未完成”流程继续处理。
- Linux 面板更新改为独立 root 更新器，不再由 Web 进程直接修改正在运行的二进制。
- 更新器安装并切换完整 Release 目录，包括 PalPanel、sav-cli、PalCalc、控制脚本和 systemd 单元。
- 新版本启动后连续验证 `/api/ready` 和 `/api/health` 中的版本；失败时恢复旧目录、旧单元和旧更新器。
- 更新过程中进程退出或主机重启后，systemd 会重新触发执行中的请求；若目标目录已经切换，则继续完成单元安装和健康验证，验证失败时回滚。

## 安全

- root 更新器独立从官方 Release 获取 `SHA256SUMS`，并再次验证下载归档。
- 包内 `checksums.txt` 必须覆盖所有普通文件；路径穿越、符号链接、硬链接、设备文件和未校验文件会被拒绝。
- 正式版本目录归 root 只读，`palpanel.service` 不再拥有 `/opt/palpanel/current/bin` 写权限。

## 修复

- 修复玩家中心的玩家列表、背包固定读取当前服务器存档，但玩家帕鲁误读当前激活存档而显示空白的问题。
- 修复 PlayerUID 在带连字符 UUID 与 32 位无连字符 GUID 之间无法匹配，导致玩家详情、背包容器和帕鲁归属读取不到的问题。
- 玩家身份匹配现在兼容 GUID 大小写、连字符差异，以及 SteamID 是否带 `steam_` 前缀。
- 玩家帕鲁查询在缺少 PlayerUID 时会回退使用当前玩家的可用存档标识，不再直接跳过查询。

## 升级说明

- 本版本首次引入 `palpanel-updater` 和 `palpanel-update.path`。从旧版本升级到本版本时，需通过新版安装脚本或手动执行新版 `palpanelctl install` 完成一次安装。
- 完成首次安装后，后续 Linux amd64 更新可继续从面板中执行。

## 验证重点

- 在玩家中心分别查看在线和离线玩家，背包与存档帕鲁应从同一个当前服务器存档索引读取。
- 同一 PlayerUID 即使后端返回 UUID 和紧凑 GUID 两种格式，也应显示为同一玩家的数据。
- 新玩家礼包选择“解锁全部科技”后，任务日志应显示科技阶段完成。
- 选择“发放科技点”后，应分别发放配置的普通科技点和古代科技点；两项均为 `0` 时应拒绝保存。
