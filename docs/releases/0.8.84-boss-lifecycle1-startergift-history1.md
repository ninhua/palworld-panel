# Palworld Panel 0.8.84 Boss 生命周期与新玩家礼包历史增量

本增量基于已经包含 `boss-fixed1` 的 0.8.84。

## 固定坐标 Boss 生命周期

- 在发送 PalDefender `/summon` 前记录日志游标，历史击杀不会计入本次 Boss。
- 固定坐标 Boss 召唤成功后保持进行中，不再把“命令发送成功”当作“Boss 已击败”。
- 按目标 PalID、模板名称和昵称匹配 PalDefender 击杀日志。
- 达到预期死亡数量后自动完成波次和召唤记录，并释放全局活动锁。
- 日志游标、死亡事件和检测进度写入 SQLite，面板重启后可恢复。
- 多面板进程通过唯一事件哈希去重；进度按数据库事件账本重新计算，不会被并发扫描回退。
- 日志轮转、截断和不完整末行均采用安全游标处理。
- 检测超时后保持活动状态并标记待人工核对，不会误判 Boss 已死亡。
- 捕捉、消失或未被当前日志格式记录的死亡不会自动完成，需要人工核对。

## 新玩家礼包历史

- 全量重新发放前，将旧发放周期完整快照保存到独立历史账本。
- 安排下次登录重新发放时保留旧周期；取消安排时撤销对应的待重发归档。
- 历史记录包含玩家身份、原状态、进度、物品/模板/科技计划、尝试次数、事件和完成时间。
- 新增 `/starter-gift-history` 页面，可搜索和筛选历史周期。
- 面板前端的重新发放、下次登录重发和取消重发均使用保留历史的接口。
- 当前发放任务和历史账本分离，历史记录不会重新进入发放队列。

## 接口

```text
GET  /api/boss/summons/{summon_id}/lifecycle
GET  /api/security/paldefender/starter-gift/history
POST /api/security/paldefender/starter-gift/grants/{player_id}/reissue-preserve
```

`reissue-preserve` 请求体：

```json
{"action":"reissue"}
```

也支持 `next_login` 和 `cancel_next_login`。

## 兼容性

- 不修改正式补丁版本，仍为 0.8.84。
- 不修改既有 Boss、袭击或新玩家礼包数据库结构；新数据表和历史 KV 按需创建。
- 旧发放周期只从安装本增量后的重新发放开始归档，无法恢复此前已经被覆盖的数据。
