# Palworld Panel 0.8.81 Boss 失败波次安全重试

维护修订：`boss-retry1`

## 功能

- 为自动 Boss 召唤增加 `retry_failed` 控制动作。
- 只允许重试最新执行尝试为 `failed` 且 `completed_commands=0` 的波次。
- `running`、`uncertain`、活动波次或部分命令已经执行时拒绝重试。
- 将失败波次恢复为 `pending`，并将召唤状态恢复为 `active`。
- 恢复因失败而被系统标记为 `summon terminated` 的后续波次。
- 保留管理员手动跳过的波次。
- 默认等待 5 秒后由自动执行器再次执行。
- 通过召唤元数据 `auto_execute_retry_delay_seconds` 可配置 0 至 3600 秒延迟。
- 记录重试次数、原执行尝试、恢复波次数量、操作者和最早执行时间。

## 调用

继续复用现有接口：

```http
POST /api/boss/summons/{summon_id}/transition
Content-Type: application/json

{"status":"retry_failed"}
```

兼容别名：`retry`、`retry_wave`、`retry_failed_wave`。

## 安全边界

- 只适用于创建时启用了 `metadata.auto_execute=true` 的召唤。
- 不会自动重试不确定结果。
- 每次失败后都需要管理员再次发起重试，不会无限循环。
- 当前没有 Boss 页面重试按钮，可通过 API 或诊断控制台调用。
