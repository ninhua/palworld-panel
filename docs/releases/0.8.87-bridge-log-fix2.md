# 0.8.87 bridge-log-fix2

本维护增量针对 PalDefender 日志桥接的历史死信和运行时触发器漂移。

## 修复

- 登录日志只提取 Steam/GDK/PS5/Xbox/EOS 平台 ID，不再把括号中的 IP 当昵称。
- UID 描述同时支持 `UID=` 与 `PlayerUID=`。
- 无视旧 v1 迁移标记，每次新服务实例都幂等确认 v2 过滤触发器存在。
- PalDefender `[Player::SendMsg::*]` 系统回包自动标记为 dismissed，不进入玩家聊天命令。
- 玩家被野生帕鲁击杀的日志不会误当作 `PAL_KILLED`，也不会继续占用待处理死信。
- `PLAYER_LOGIN` 死信会按唯一 SteamID 从 `economy_accounts` 补齐 PlayerUID，保留 pending 供管理员按需重放。

## 关于截图中的商城错误

截图中 `商城` 的 `sql: no rows in result set` 发生在 shop-fix1 合入前。0.8.87 已包含账户解析和商城诊断修复；升级后先发送一次“商城”验证。旧的纯列表查询死信可直接忽略或关闭，无需重放。

## 部署后

1. 重启面板，等待约 1 秒完成 v2 自愈。
2. 刷新“积分系统 → 事件死信”。系统回包和玩家死亡噪声应从待处理数量中消失。
3. 对仍为 pending 且已经补齐 PlayerUID 的 `PLAYER_LOGIN`，仅在配置了登录类任务时重放；否则可关闭。
4. 确认页面版本至少为 0.8.87。
