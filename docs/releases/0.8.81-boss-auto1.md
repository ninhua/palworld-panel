# 0.8.81 Boss 自动续波维护增量 1

本增量建立在 `custom-stable` 的 `0.8.81` 上，不改变面板补丁版本号和 OpenAPI 合同版本。

## 新增

- 对召唤记录提供显式启用的自动续波执行器。
- 每一波按照该波的 `delay_seconds` 计算最早执行时间。
- 面板重启后重新扫描数据库中的待执行召唤；Boss 服务和 RCON 适配器恢复后继续。
- 每个扫描周期最多执行一波，避免多波在同一时间突发执行。
- 检测到活动波次、运行中尝试或 `uncertain` 尝试时立即停止自动推进。
- 失败和不确定结果不自动重试，继续沿用 0.8.81 的人工核对规则。

## 启用

创建 Boss 召唤记录时，在 `metadata` 中加入：

```json
{
  "auto_execute": true
}
```

可选的最早启动时间：

```json
{
  "auto_execute": true,
  "auto_execute_not_before": "2026-08-03T20:00:00+08:00"
}
```

预置暂停：

```json
{
  "auto_execute": true,
  "auto_execute_paused": true
}
```

## 安全边界

- 未显式设置 `auto_execute=true` 的旧召唤记录不会自动执行。
- 自动执行器只有在 Boss 服务已经配置 RCON 执行适配器后才工作。
- 当前维护增量尚未增加面板上的暂停/继续按钮；`auto_execute_paused` 主要供 API 创建流程和后续控制接口使用。
- 当前仍不判断 Boss 是否被击杀；每一波成功发送并得到确定 RCON 响应后，才按延迟推进下一波。
