# PalPanel patch 0.8.63

## 商城批量交付与审计

本版在 `0.8.62` 自动交付状态机基础上补齐运营维护能力。

### 批量自动交付

新增安全的批量处理接口：

```text
POST /api/shop/maintenance/deliver
```

默认按创建时间顺序处理最多 20 个自动交付订单，单次上限 50 个。批量任务串行执行，避免同时向 PalDefender 发起大量写请求。

- 默认选择 `pending` 和 `succeeded` 状态。
- `succeeded` 只重试积分结算，不会再次发放。
- 只有显式设置 `include_failed=true` 才会重试明确失败的订单。
- `processing` 订单始终跳过，必须先人工核对。
- 每个订单独立返回 `delivered`、`failed`、`uncertain` 或 `skipped`。
- 单个订单失败不会中止整个批次。

### 交付审计

新增持久化审计表 `shop_delivery_events`，记录：

- 订单创建和积分预留。
- 自动交付开始。
- 明确失败或结果不确定。
- 游戏内发放成功。
- 管理员人工重置。
- 订单结算或取消退款。

审计事件包含订单 ID、交付状态、尝试次数、操作者、时间和受限详情。查询接口：

```text
GET /api/shop/delivery-events
```

支持按 `order_id` 和 `event_type` 筛选。

### 订单筛选和页面

订单列表新增：

- `delivery_state` 筛选。
- `delivery_mode` 筛选。
- 自动交付订单快捷筛选。
- 批量交付控制和“包含失败订单”显式开关。
- 交付审计页签。
- 失败订单与待人工核对订单分开统计。

### API

新增：

```text
GET  /api/shop/delivery-events
POST /api/shop/maintenance/deliver
```

OpenAPI 当前包含 309 个操作。
