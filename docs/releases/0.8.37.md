# PalPanel 自定义版 0.8.37

发布日期：2026-07-29

## 新增

- 新增“通知与事件”中心，统一归并监控告警、PalServer 崩溃熔断和失败后台任务。
- 相同根因按去重键累计次数；已解决事件再次发生时自动重新打开。
- 新增事件列表、详情、确认、解决、重新打开和签名 Webhook 测试接口。
- 新增可选 HMAC-SHA256 Webhook，携带固定 Delivery ID、事件类型和时间戳。

## 安全与可靠性

- 后台任务事件只保存任务 ID、类型和稳定错误码，不保存原始错误、日志正文或文件路径。
- Webhook API 不返回完整目标 URL或密钥；远程目标必须使用 HTTPS，HTTP 仅允许回环地址。
- 禁止 Webhook 重定向，固定超时，最多重试 6 次；最终失败不会生成递归事件。
- 事件状态写入串行化，避免同一根因并发产生重复记录或覆盖状态。
- 已解决事件保留 90 天，状态变化进入事件时间线和操作审计。

## 升级注意事项

- 数据库 schema 升级到 13，自动创建事件、时间线、任务关联和投递队列表。
- Webhook 默认关闭。启用时设置 `PALPANEL_INCIDENT_WEBHOOK_URL` 和至少 16 字符的 `PALPANEL_INCIDENT_WEBHOOK_SECRET`，随后重启面板。
- 无 systemd 的启动脚本环境可以直接使用站内事件中心和 Webhook。

## 验证重点

- 相同告警或失败任务根因不得重复创建事件，只增加 occurrences。
- 解决后的事件再次发生应自动重新打开。
- Webhook 签名应匹配 `HMAC-SHA256(secret, timestamp + "." + body)`，接收方按 Delivery ID 去重。
- API 与 Webhook 载荷不得出现签名密钥、完整 URL、任务原始错误或服务器路径。
- GitHub Actions 应通过 Go、前端、OpenAPI、Linux/Windows 和安全检查。

完整比较：`v1.3.0-custom.0.8.36...v1.3.0-custom.0.8.37`
