# PalPanel 自定义版 0.8.36

发布日期：2026-07-29

## 新增

- 新增 PalServer 崩溃守卫，持续识别异常退出、OOM 和 Docker 自动重启循环。
- 10 分钟内累计 3 次异常后自动熔断；Docker 会先关闭自动重启策略再停止容器。
- 新增 `GET /api/server/crash-guard` 和 `POST /api/server/crash-guard/recover`。
- 监控页显示熔断状态、最近异常和诊断控制台入口，可选择仅解除熔断，或解除后重新启动服务器。

## 安全与可靠性

- PalPanel 发起的手动停止、安全重启和配置应用不会计入崩溃。
- 观察线程与生命周期线程串行更新守卫状态，避免并发检查覆盖“预期停服”标记。
- 熔断期间拒绝配置应用和世界重置；服务端更新仍可用于修复，但完成后保持停服，管理员确认恢复后才启动。
- 熔断状态持久化，重启 PalPanel 不能绕过启动阻断。
- 恢复会关闭崩溃守卫告警并从恢复时间重新计算窗口，旧事件保留展示但不会立即触发再次熔断。
- 恢复启动失败时重新进入熔断，避免反复启动。
- 事件仅保存运行模式、退出码、OOM、重启次数和时间，不保存路径、日志正文或玩家信息。

## 升级注意事项

- 数据库 schema 升级到 12，自动创建崩溃守卫状态与事件表。
- 无 systemd 的启动脚本环境可直接使用；该功能由 PalPanel 进程自身监督。
- 默认阈值目前固定为 10 分钟 3 次。

## 验证重点

- Docker 容器连续失败三次后应执行 `docker update --restart=no`，随后停止容器。
- 手动停服和安全重启不得增加崩溃计数。
- 熔断后普通启动与重启应返回 HTTP 409；确认恢复后才可启动。
- GitHub Actions 应通过 Go、前端、OpenAPI、Linux/Windows 和安全检查。

完整比较：`v1.3.0-custom.0.8.35...v1.3.0-custom.0.8.36`
