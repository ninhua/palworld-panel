# PalPanel patch 0.8.58

## 新增

- 新增事件驱动任务引擎，消费统一游戏事件账本。
- 支持每日、每周和永久一次任务周期。
- 支持按事件类型、Payload 等值过滤和数量字段推进任务。
- 达标奖励通过统一积分账本发放，使用任务和周期引用保证幂等。
- 新增任务定义、玩家进度和失败奖励重试 API。
- 游戏事件处理结果增加 `tasks` 字段，记录本次推进、完成和奖励状态。

## 新增接口

- `GET /api/tasks`
- `POST /api/tasks`
- `PUT /api/tasks/{id}`
- `DELETE /api/tasks/{id}`
- `GET /api/tasks/progress/{player_uid}`
- `POST /api/tasks/maintenance/retry-rewards`

以上接口已经同步加入 `docs/openapi.yaml`，不会再次触发路由契约缺失。

## 数据安全与幂等

- 任务进度按玩家、任务和周期隔离。
- 单个游戏事件对同一任务只计数一次。
- 单个玩家在同一任务周期只建立一笔奖励。
- 积分流水使用 `task_reward` 引用类型；重试不会重复加分。
- 删除任务采用归档，不清理历史进度和奖励审计。
- 奖励发放失败会保留为 `failed`，可通过事件重试或维护 API 恢复。

## 当前限制

- 本版提供后端任务引擎和 API，尚未加入任务管理前端页面。
- 游戏事件仍需 AstrBot、PalDefender 事件桥或其他受信任程序签名上报。
- 任务奖励当前为统一积分；物品、帕鲁和 Boss 掉落将在后续版本接入奖励执行器。

## 验证范围

- 任务包通过隔离 Go 编译和逻辑单元测试。
- API 文件通过 Gin、SQLite 和 PalDefender 隔离编译检查。
- 8 条 SQLite 建表和索引语句通过实际 SQLite 执行及约束验证。
- OpenAPI YAML 解析成功，263 个路径条目中包含全部 6 个新增任务操作。
- 覆盖包 ZIP 路径、文件校验和及完整性检查。

完整仓库 CI 仍需在应用覆盖包后执行。
